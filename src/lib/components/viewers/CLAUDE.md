# viewers/

Per-format viewer components. Routed by `ViewerRouter` based on file extension.

**STAC routing rule**: `ViewerRouter::detectStac` only returns `{ kind: 'stac', ... }` when `classifyStac(parsed)` recognises the JSON as a STAC Item / ItemCollection / Collection / Catalog. Plain JSON that happens to parse (including GeoJSON FeatureCollections that fail the STAC shape check) returns `{ kind: 'none' }` so the router falls through to `CodeViewer`; otherwise StacTabViewer's `stac-map` / `STAC Browser` buttons would appear on files that have nothing to do with STAC. Parquet files route through `detectStacGeoparquet`, which keys on the schema's top-level columns.

**Pending-state gate**: `detectStac` (256 KB JSON peek + parse) and `detectStacGeoparquet` (parquet schema sniff) are async, so `stacRoute` transits through `{ kind: 'pending' }` between mount and resolution. While pending, `ViewerRouter` mounts an empty pane for `viewerKind === 'table' | 'code' | 'raw'` instead of falling through to plain `TableViewer` / `CodeViewer`. Without this gate, the transient viewer reads the URL hash, picks a default `viewMode`, and may stamp `updateUrlView(...)` over the hash that the eventual `StacTabViewer` mount would have honoured (e.g. `#map` on a STAC Collection JSON gets clobbered to `#stac-browser` by `CodeViewer`'s `isStacJson` auto-switch). The pending window is short (small file = single peek; large file falls back to a full read inside `detectStac`). Other viewer kinds skip the gate because their detection is synchronous.

**URL view-mode rule**: every viewer with a `viewMode` state derives its initial value through `pickViewMode<T>(validModes, defaultMode)` from `utils/url-state.ts`. The helper (a) validates the URL hash against the viewer's known token vocabulary and (b) falls back to `defaultMode` WITHOUT rewriting the URL. Critical invariant: a viewer MUST NOT call `updateUrlView(...)` for a hash it doesn't recognise — that hash is owned by another viewer farther up the routing stack and will become valid once the routing decision settles. The pending-state gate above defends the same invariant at the router level; `pickViewMode` defends it at the viewer level.

The slim `MosaicSourceMeta[]` and the rich `StacItemView[]` move together at every transition point. **Layer model (declarative, single-derive)**: there is NO imperative `currentMosaicLayer` / `pushLayers` path. The full deck.gl layer set is a pure function of `(committedSources, committedViews, bandConfig, rescale, pipelineGen, showFootprints, hoveredId, selectedId, filterState)` derived through `$derived mosaicLayer`, `$derived footprintLayer`, and `$derived layers`. A single `$effect` calls `overlayRef.setProps({layers})` when any input changes. **Critical dep-tracking gotcha**: the push effect MUST read `const ls = layers;` BEFORE its `if (!overlayRef) return;` early exit. Read first, guard second. Layer identity is content-hashed: `mosaicId = mosaic-${hashSources(filteredItems)}-p${pipelineGen}`. Same content → same id → deck.gl reconciles in place via `_transferLayerState`. Different content (sources change, pipeline change) → different id → deck.gl does a clean unmount/init pair. **This is what removes the `assert9(!this.internalState)` deck.gl assertion that fired in the previous imperative model**: nothing in the rewritten viewer ever re-presents a finalized COGLayer instance to the layer tree, because deck.gl is the only entity that holds layer instances. `commitSources()` is the single transition point that promotes the streaming buffer (`itemsRef`/`itemViewsRef`) to the rendered set; `bumpPipeline()` is the single transition point for invalidating the inner TileLayer's tile cache on band/rescale change. The footprint layer is a `@deck.gl/layers GeoJsonLayer` over bbox polygons with `updateTriggers` on `getLineColor`/`getLineWidth`/`getFillColor`, so hover/select/filter changes re-run the per-feature accessors without rebuilding the layer or re-tessellating geometry. `filled: true` with a near-transparent default fill (`[0, 0, 0, 1]`) is required because deck.gl's GeoJsonLayer hit test only covers the stroke edge when `filled: false` — clicks inside the polygon would never fire `onClick` and the yellow selection highlight would never appear. `lineWidthMinPixels: 1` keeps the orange grid from anti-aliasing to invisible at low zoom. `hoveredId` and `selectedId` are plain `$state<string | null>` synced bidirectionally between the strip card hover, footprint pick events, and the inspector. **Strip / inspector**: `StacItemStrip` renders bottom-anchored cards with thumbnail + datetime + cloud-cover badge, lazy-loads thumbnails via the parent's `presignHref` (sharing the LRU presign cache so private buckets work without a duplicate cache), drops thumb URLs for items no longer in the views list, and scrolls the selected card into view when selection comes from a footprint click. `StacItemInspector` is a right-side slide-over showing datetime / cloud / gsd / platform / constellation / instruments / EPSG / bbox + asset table with per-asset Open links (presigned on click) + a collapsible raw JSON section with copy-to-clipboard. **Memory model**: `geotiffCache`, `presignCache` (keyed by href), and `sourceHistograms` are all bounded LRU / Map structures that get swept by `MosaicLayer.onTileUnload` so deck.gl's own tile-eviction signal drives Svelte-side cache eviction symmetrically (cap = `SOURCE_CACHE_MAX = 64`, also passed as `MosaicLayer.maxCacheSize`). A reverse `sourceHrefById: Map` maps a deck.gl-evicted source.id back to its href so the matching `presignCache` entry can be dropped at the same time. **Commit model**: streaming batches mutate `itemsRef`/`itemViewsRef` (the buffer) freely; the renderer reads `committedSources`/`committedViews` only. `commitSources()` is called at strategic boundaries: api-backed sources commit on the first batch (atomic swap so the user sees a frame fast) and once after the stream completes (final flush) — intermediate pages stay in the buffer so the inner TileLayer cache is not churned mid-pan. Trade-off: a long-running stream (e.g. 10s for 2000 items) shows only the freshest page until the stream completes; this is acceptable because the freshest page is what the user actually sees at the current zoom, older pages are dimmer revisits that mostly overlap the first, and the final flush is a single declarative re-derive. Static and parquet sources commit per batch. There is no rebuild timer; the derived chain re-runs synchronously when `committedSources` changes, and deck.gl's id-based reconciliation does the right thing. **`commitSources()` also enforces dedup-by-id**: the same `item.id` can appear across pagination batches (revisits with different `spatialCellKey`, static catalogs that re-walk overlapping links, API pages that overlap the previous response). The accept-site `seenIds` defends within one `loadMosaic` call but is not load-bearing — the commit boundary is the single chokepoint before the renderer, and the keyed `{#each views as view (view.id)}` in `StacItemStrip` would throw `each_key_duplicate` if duplicates leaked through. Both arrays are filtered by the same predicate so they stay lockstep. **Abort model**: `abortController` is viewer-lifetime (only torn down on tab close / reset), `hydrationController` is per-pan (aborts only the JSON link-walk so in-flight COG range fetches keep painting visible tiles); both are filtered through `isAbortError` in `onTileError` and `MapboxOverlay.onError` to stop console floods. See root `CLAUDE.md` "Map / deck.gl Viewer Memory Checklist". **Open-time smoke test + Explain panel + overview-aware pixel inspection**: at viewer mount the first picked asset's presigned href is run through `smokeTestHref(href, signal)` and on failure an amber HUD pill (`stac.smokeWarning` / `stac.smokeWarningHint`) is rendered so presign / CORS / 403 errors are visible without waiting for the first tile fetch. The Info panel gained an `Explain` section (`stac.explainHeading` + `stac.explainItems` / `stac.explainAssets` / `stac.explainOverlap` / `stac.explainBytes` / `stac.explainTimeSpan`) reporting items visible / total, distinct asset keys across the picked mosaic, center-overlap count, estimated tile bytes, and the time span of the visible set, so a user can see why a viewport is dense or sparse. Click-to-inspect now mirrors `CogViewer`'s overview-aware pattern, the topmost source whose bbox contains the click is found in z-order and `readPixelAtLngLat(geotiff, lng, lat, {overview: selectOverviewForResolution(geotiff, mapResolutionMetersPerPixel(zoom, lat))})` reads the same overview deck.gl is painting instead of always falling back to full-res. |

## CogControls

Shared style/picker panel mounted by `CogViewer`, `MultiCogViewer`, and `StacMosaicViewer`. Single prop shape (`assets: CogAsset[]`, `composite: ChannelComposite`, `presets: PresetDef[]`, plus mode toggle for the legacy single-band ramp branch). Renders a top-of-panel preset `<select>` (Natural color / False-color IR / SWIR / Vegetation / Agriculture, NDVI intentionally excluded), then three `ChannelPicker` rows (R/G/B, optional A) when mode='rgb', then the existing single-band ramp picker (107-entry sprite, search, pinned grid) when mode='single'. The band column inside each ChannelPicker auto-collapses to plain `Band 1` text when the chosen asset's `bandCount === 1`, so Sentinel-2 / Landsat per-band assets read as one clean row while NAIP `image` / S2 `visual` exposes the full band picker. Histogram overlay + rescale slider unchanged.
